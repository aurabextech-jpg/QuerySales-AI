# Phase Summaries

One file per completed phase. **Writing the summary is part of the phase, not an afterthought —
a phase is not complete until its summary exists here.**

Rules and the full workflow: [AGENTS.md §5](../../AGENTS.md#5-phase-workflow--mandatory).

## Naming

```
phase-<N>-<kebab-slug>.md
```

## Template

Copy [_TEMPLATE.md](_TEMPLATE.md).

## Why this exists

`AGENTS.md` §7–§9 is the **index** — the small, durable context every session loads first.
This folder is the **archive** — the detail behind each index line: what was built, what was
actually verified and with which command, what was deferred and why, and what a later phase now
needs to know.

Two rules keep it useful:

1. **Record real results, not intentions.** A summary saying a check passed when it was never run
   is worse than no summary — it removes the reason for anyone to check again.
2. **Write down what the code cannot say.** File lists are recoverable by reading the repo.
   Rationale, dead ends, provider quirks, and rejected alternatives are not.
